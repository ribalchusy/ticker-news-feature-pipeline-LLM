# ticker-news-feature-pipeline-LLM

Проект представляет собой пайплайн для преобразования русскоязычных финансовых новостей в структурированные признаки, которые можно использовать в задачах машинного обучения для рыночных данных.

```text
финансовые новости
        ↓
очистка и нормализация
        ↓
привязка к тикерам
        ↓
LLM/NLP-обогащение
        ↓
классификация событий
        ↓
rolling news features
        ↓
model-ready feature table
```

На выходе получается таблица признаков по схеме:

```text
datetime | ticker | news_count_24h | sentiment_avg_24h | dividends_count_24h | ...
```

Эту таблицу можно присоединять к рыночным данным и использовать в downstream ML-задачах, например для классификации торгового сигнала, анализа влияния новостного фона или сравнения моделей с новостными признаками и без них.

---

## Цель проекта

Цель проекта — построить воспроизводимый pipeline, который переводит неструктурированные финансовые тексты в числовые признаки, выровненные по времени с рыночной сеткой.

Проект демонстрирует:

- обработку русскоязычных финансовых новостей;
- привязку новостей к тикерам;
- использование LLM-generated descriptions;
- rule-based event extraction;
- построение rolling-признаков по новостям;
- предотвращение утечки данных из будущего;
- подготовку model-ready таблицы признаков.

---

## Что делает проект

Проект выполняет следующие шаги:

1. Загружает и нормализует русскоязычные финансовые новости.
2. Обрезает данные до общего периода, где есть и новости, и рыночная временная сетка.
3. Привязывает новости к выбранным MOEX-тикерам по названиям компаний и aliases.
4. Использует предрассчитанные LLM-описания из открытого Kaggle-датасета.
5. Преобразует LLM-описания и текст новости в структурированные события.
6. Строит rolling-признаки за окна 1h, 6h, 24h и 72h.
7. Сохраняет финальную model-ready таблицу признаков.

---

## Используемые данные

Проект использует открытый датасет **Russian Financial News** с Kaggle.

Сырые данные не хранятся в репозитории, потому что они слишком большие для GitHub.

## Рабочий период

Новости в Kaggle-датасете доступны до декабря 2024 года, а рыночные данные покрывают более широкий период.

Чтобы избежать ситуации, где рыночные данные есть, а новостного покрытия уже нет, проект использует только общий пересекающийся период.

Финальный рабочий период:

```text
2024-01-03 09:00:00 → 2024-12-13 23:00:00
```
---

## Выбранные тикеры

В проекте используются 10 MOEX-тикеров:

```text
SBER
GAZP
ROSN
NVTK
GMKN
PLZL
TATN
AFLT
YDEX
VKCO
```

Для каждого тикера задан набор aliases, по которым новости связываются с компанией.

Примеры:

```text
SBER → сбербанк, сбер, sberbank
GAZP → газпром, gazprom
ROSN → роснефть, rosneft
YDEX → яндекс, yandex
VKCO → вконтакте, vk company, vk group, mail.ru
```
